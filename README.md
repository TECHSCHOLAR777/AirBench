# AirBench

### Sovereign, Provenance-Preserving AI Workbench for Mission-Critical Engineering

**Plan locally. Execute deterministically. Keep every calculation grounded in authoritative evidence, and verify which conclusions were observed from signed documents and which were proposed by local models.**

![The AirBench Sovereign Task Command workspace](docs/assets/airbench_workspace.png)
*The AirBench workspace: Local on-premises enclave (4× GPU cluster, 8 AI workers) operating over loopback zero-egress (`127.0.0.1:8080`), multimodal engineering intake (.pdf, .docx, .xlsx, P&ID CAD drawings), specialized local model routing, deterministic calculation sandboxing, and real-time auditable conversation logs.*

## Overview

Industrial, energy, defence, and public-sector engineering facilities—such as thermal power plants, battery energy storage systems (BESS), chemical fluid networks, and critical utilities—rely on confidential technical specifications, Piping and Instrumentation Diagrams (P&IDs), operating manuals, and unreleased designs. These assets cannot leave the organization's controlled physical perimeter. Standard cloud LLMs pose catastrophic intellectual property risks, leak operational telemetry, and lack physical determinism. Autonomous ReAct agents compound this failure mode by entering unconstrained execution loops, hallucinating calculations, and presenting unsupported narrative prose as engineering truth.

AirBench treats mission-critical engineering knowledge work as a **constrained, verifiable state-transition inverse problem with deterministic verification projections**. An engineering query over untrusted documents and schematic evidence is formulated as discovering a compliant deliverable state $x^*$ consistent with physical laws (first-principles thermodynamics, Darcy-Weisbach friction loss, mass-energy balances), domain regulations $\mathcal{R}$, and operator clearance $\mathcal{C}$. AirBench decomposes every intermediate result into:

1. An **observed fact envelope** $y = \mathcal{A}(D, E)$, strictly extracted from signed source documents, OCR bounding regions, and topological P&ID graph extractions; and
2. An **inferred proposal** $z$ in the hypothesis space generated by qualified local models (via vLLM and NVIDIA NIM).

AirBench's deterministic control plane enforces that neural models act *strictly* as hypothesis proposers—never driving execution loops, mutating state machines, or granting themselves tools. All proposals are projected onto the invariant manifold of authoritative sources and deterministic solvers:

$$\hat{x} = \Pi_{\mathcal{M}_{\text{physics}} \cap \mathcal{R}}(z \mid y)$$

Deliverable numerical values are calculated by deterministic Python solvers, factual confidence is calibrated via Mondrian conformal prediction, and every consequential action is permanently written to an append-only, signed cryptographic audit ledger.

## Features

- **Sovereign, Zero-Egress Enclave.** Runs entirely on-premises on local GPUs over loopback sockets (`127.0.0.1:8080`). Strictly zero external network access, preventing telemetry leakage or external data exfiltration.
- **Observed versus Proposed Separation.** Uploaded files are strictly treated as untrusted data. Neural models propose candidate text in the unobserved hypothesis space; authoritative values and state transitions remain owned by the deterministic control plane.
- **ReWOO Decoupled Execution.** Replaces unbounded ReAct loops with structured Plan-Worker-Solver execution graphs (Xu et al., 2023), eliminating token-wasting tool hallucination and non-deterministic agent drift.
- **P&ID2Graph Visual Engineering Digitization.** Converts complex Piping and Instrumentation Diagrams into topological property graphs (Rahul et al., 2024), extracting pumps, valves, instruments, and line connectivity with pixel-grounded bounding boxes.
- **Semantic & In-Context Model Routing.** Dual-tier model routing combining sub-millisecond Semantic Router embeddings (Patel et al., 2024) and dynamic in-context allocation via ICLRouter (Ding et al., 2024) across specialized local vLLM endpoints.
- **Deterministic Physics & Calculation Solvers.** Thermodynamic cycles, Darcy-Weisbach friction losses, BESS thermal runaway kinetics, and mass-energy balances are computed by deterministic code in an isolated sandbox, never generated by probabilistic token sampling.
- **Mondrian Conformal Confidence Calibration.** Utilizes Mondrian conformal prediction (Angelopoulos & Bates, 2023) to state distribution-free uncertainty guarantees across heterogeneous engineering document types and asset classes.
- **Production Office Deliverables.** Emits publication-grade Word documents with source anchors, Excel workbooks with live mathematical formulas, PowerPoint decks, and sandboxed code packages.
- **Continuous Append-Only Audit Ledger.** Cryptographic SHA-256 hash-chained ledger logging all intake manifests, model prompts, tool outputs, verification gates, and human sign-offs for offline compliance audits.

## Using AirBench

### Enclave Specification

| Requirement | Value |
| :--- | :--- |
| **Deployment Target** | Air-gapped workstation, on-premises server, or sovereign enclave cluster |
| **Compute & Acceleration** | 1× to 4× NVIDIA GPUs (RTX 4090, A100, H100) running local vLLM / TensorRT-LLM |
| **Network Invariant** | Strict Zero-Egress, local loopback (`127.0.0.1:8080`), isolated IPC |
| **Document Intake** | PDF, DOCX, XLSX, PPTX, Markdown, P&ID CAD drawings (.png, .jpg, .dxf) |
| **Serving Backends** | vLLM (PagedAttention), NVIDIA NIM, llama.cpp / GGUF local engines |
| **Routing Framework** | Semantic Router (embedding classification) + ICLRouter (demonstration-based allocation) |
| **Desktop Interface** | Tauri 2.0 shell, React 19, TypeScript, Dark Engineering Cockpit |
| **Deliverable Formats** | Word (.docx), Excel (.xlsx with formulas), PowerPoint (.pptx), verified code packages |

### Quickstart

#### 1. Python Enclave Runtime
```bash
# Initialize isolated Python environment
python -m venv .venv

# Activate environment
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell:
# .venv\Scripts\Activate.ps1

# Install core runtime and test harnesses
python -m pip install -e ".[test]"

# Run verification test suite
pytest
```

#### 2. Start Local Model Serving (vLLM)
```bash
# Launch qualified model workers via vLLM on local GPU cluster
vllm serve Qwen/Qwen2.5-Coder-32B-Instruct --port 8000 --tensor-parallel-size 2
vllm serve deepseek-ai/DeepSeek-R1-Distill-Qwen-14B --port 8001 --tensor-parallel-size 2
```

#### 3. Launch Sovereign Desktop Cockpit
```bash
cd apps/desktop
npm ci
npm run check:contracts
npm run tauri:dev
```

## The AirBench Workspace

The desktop application provides a sovereign, high-density engineering command center:

- **Enclave Status Bar:** Real-time monitoring of enclave security (`Sovereign Enclave Active`), loopback transport (`127.0.0.1:8080`), cluster health (`Enclave Cluster: Online`), and zero-egress enforcement.
- **Left Navigation Rail:** Dedicated views for the main command cockpit (`Home`), schematic topology viewer (`P&ID`), isolated execution shell (`Sandbox`), local manuals (`Knowledge`), verification queue (`Review`), and network firewall inspector (`Network`).
- **Cluster Hardware Monitor:** Displays active local compute topology (e.g. `4 GPU local · 8 AI workers`, `AirBench Node 01`, `Enclave v0.1.0`).
- **Sovereign Task Command:** Unified query input supporting multi-format document attachment (.pdf, .docx, .xlsx, .ppt, .md), output format selection, auto-dispatch enclave routing, and execution controls.
- **Audit & Conversation Drawer:** Sequence-numbered ledger events, ReWOO task progress, verification badges, and human-in-the-loop review checkpoints.
