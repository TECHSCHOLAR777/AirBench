# Slide patterns

## Five dominant features

Use this pattern when a non-technical audience asks for five features without further constraints. Start with the benefit people can feel, then explain the controls that make it credible.

- Runs inside the organization, keeping confidential files, models, and task execution on premises.
- Creates review-ready documents, workbooks, presentations, code, and calculations with clear supporting evidence.
- Reads scanned documents and P&IDs, linking findings to the exact source region for review.
- Combines local document search with a World Model that connects organizational facts and decisions.
- Runs multi-step work under user control, with qualified models, safe tools, and recorded checks.

## Product problem

Write three to four bullets. Each should name a sensitive work item, the failure of ordinary chat tools, and the operational consequence. Do not describe the problem as generic productivity loss.

## System architecture

Use a four-part narrative.

1. Controlled intake turns local files into bounded evidence.
2. Retrieval and the World Model provide cleared evidence to the orchestrator.
3. Qualified workers and governed tools complete bounded stages.
4. Verification, delivery, review, and the ledger make the result checkable.

## Sovereignty and safety

Each bullet must contain a mechanism and its proof.

- No-network execution isolates code and untrusted file processing from external access.
- Clearance filtering limits evidence exposure during retrieval and final artifact delivery.
- Signed ledger events reconstruct who acted, which evidence was used, and what artifact was produced.

## Demonstration flow

Use visible actions in order.

1. Upload a scanned report through File Intake.
2. Show extracted evidence, source regions, and confidence.
3. Show cleared retrieval and the orchestrator plan.
4. Show model route, tool execution, and verification outcome.
5. Open the verified deliverable and its local audit trace.
