# AirBench capability map

Use this reference to select accurate claims for presentation content. Keep the core engine and domain pack separate.

## Product boundary

AirBench is a sovereign AI worker for sensitive organizational work. It runs inside the organization, keeps sensitive material on controlled infrastructure, and produces checkable deliverables rather than a chat response alone.

The desktop application is the user-facing command and evidence surface. It creates tasks, accepts attachments through File Intake, shows the plan, progress, evidence, questions, approvals, artifacts, and local audit trace. The AirBench Node owns admission, state, execution, policy checks, and authoritative records.

The core engine is sector-neutral. The signed domain pack declares document profiles, world-schema types, authoritative sources, verification rules, clearance and need-to-know policy, autonomy rules, and deliverable templates.

## Evidence and knowledge

- File Intake is the only parsing path for bulk ingestion and task uploads.
- Documents, spreadsheets, PDFs, scans, images, and drawings remain untrusted data.
- Evidence keeps source, source region, confidence, clearance, taint, revision, content hash, derivation, and time references.
- Local retrieval returns clearance-filtered cited excerpts. It does not expose bare document text or permit content to grant authority.
- The World Model stores evidence-bearing objects and relationships from authoritative records. It answers connected and time-scoped questions that document search cannot answer.

## P&ID and visual evidence

- The controlled P&ID adapter processes drawings through visual intake and qualification.
- It can produce coordinate-grounded symbol, text, line, relationship, and graph-fragment evidence.
- The result remains reviewable against the source drawing. It is evidence, not an unquestionable engineering conclusion.

## Task execution

- The deterministic orchestrator owns task state, plans, retries, fallbacks, worker dependencies, approval gates, and completion.
- Models are stateless workers. They propose bounded outputs and never grant authority.
- The harness can schedule one worker, a serial virtual team, a pipeline, or parallel workers according to qualified capability and the measured hardware profile.
- The router selects only qualified local targets after checking task kind, modality, clearance, context, risk, model qualification, health, and hardware admission.
- The Tool Gateway validates typed actions. The isolated sandbox executes code and calculations without a network path.

## Verification, delivery, and proof

- Verification checks source support, deterministic calculations, domain-pack rules, units, bounds, and artifact requirements.
- Consistency checks compare relevant current decisions and flag unexplained deviations.
- The Autonomy Governor determines whether an action can proceed, needs review, or must be denied.
- The Deliverable Engine renders DOCX, XLSX, PPTX, code, calculation, and drawing-evidence outputs from verified bindings and pack templates.
- Models write bounded prose. Deterministic records own values, formulas, chart ranges, layout controls, hashes, and checks.
- The signed append-only ledger records facts, task transitions, routing decisions, calls, tool actions, verification outcomes, review actions, artifacts, previews, and downloads.
- Sovereignty proof combines local isolation, no-egress checks, local process and model identity records, and replayable ledger evidence.

## Complete-product presentation posture

For presentation copy, describe these connected parts as one finished system. A sensitive request becomes a bounded task, local files become evidence, the orchestrator coordinates qualified workers and tools, deterministic checks govern completion, and the Deliverable Engine returns a reviewable artifact with a replayable audit record. Do not reduce AirBench to a private model, a document chatbot, a vector search tool, or a P&ID detector.
